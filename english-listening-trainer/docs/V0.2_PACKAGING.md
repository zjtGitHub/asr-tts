# v0.2 macOS Packaging Guide

This stage packages the existing Python + FastAPI + `faster-whisper` backend as an Apple Silicon Tauri sidecar. The packaged application no longer requires the end user to install Python, pip, or create a virtual environment.

## Runtime design

Development remains unchanged:

```text
npm run tauri dev
  -> scripts/dev_backend.py
  -> .venv/bin/python
  -> FastAPI on 127.0.0.1:8000
  -> Tauri loads the development URL
```

Release builds use a bundled executable:

```text
English Listening Trainer.app
  -> Tauri release process
  -> bundled english-listening-backend sidecar
  -> embedded Python runtime + FastAPI + faster-whisper
  -> backend listens on 127.0.0.1:8000
  -> bundled Web UI calls the local backend
```

The Whisper model itself is intentionally not bundled. On first transcription, `faster-whisper` may download the configured model and cache it on the user's machine.

## Supported target

For v0.2 packaging:

```text
macOS Apple Silicon arm64
Rust host: aarch64-apple-darwin
```

Intel Mac and Windows packaging are intentionally out of scope.

## 1. Pull the latest branch

```bash
git checkout feature/english-listening-trainer
git pull
cd english-listening-trainer
```

## 2. Install build dependencies

Activate the existing project environment:

```bash
source .venv/bin/activate
```

Install runtime + packaging dependencies:

```bash
pip install -r requirements-build.txt
```

Install/update Tauri's Node dependency after the Rust shell plugin/config changes:

```bash
npm install
```

## 3. Confirm the development app still works

```bash
npm run tauri dev
```

Verify the existing features still work before doing a release build:

- audio upload;
- Whisper transcription;
- click transcript row to seek;
- current sentence highlighting;
- auto-follow;
- locate-current;
- hide/show subtitles.

Stop the dev process before the next steps so port `8000` is free.

## 4. Build only the Python sidecar

```bash
npm run backend:build
```

The script checks the platform/toolchain and runs PyInstaller in one-file mode. The expected result is:

```text
src-tauri/binaries/english-listening-backend-aarch64-apple-darwin
```

The `src-tauri/binaries/` directory is generated and intentionally ignored by Git.

### Sidecar smoke test

Run the generated executable directly:

```bash
./src-tauri/binaries/english-listening-backend-aarch64-apple-darwin
```

In another terminal:

```bash
curl http://127.0.0.1:8000/health
```

Expected response:

```json
{"status":"ok"}
```

Stop the sidecar with `Ctrl+C` before building/running the desktop release.

## 5. Build the `.app` and `.dmg`

Run the complete build command:

```bash
npm run desktop:build
```

This command:

1. generates the macOS icon sizes from `src-tauri/icons/icon.png`;
2. builds the Apple Silicon Python backend sidecar;
3. runs Tauri's release build with `src-tauri/tauri.release.conf.json`;
4. bundles the sidecar through `bundle.externalBin`;
5. requests both `.app` and `.dmg` outputs.

Expected output locations:

```text
src-tauri/target/release/bundle/macos/English Listening Trainer.app
src-tauri/target/release/bundle/dmg/
```

## 6. Verify that the packaged app does not depend on `.venv`

First make sure no development backend is running on port 8000.

Deactivate the Python environment if desired:

```bash
deactivate
```

Then open the generated `.app` from Finder, or:

```bash
open "src-tauri/target/release/bundle/macos/English Listening Trainer.app"
```

The app should launch the bundled backend automatically. Do not run `python app.py` and do not run the sidecar manually.

Repeat the functional checks:

- choose an audio file;
- transcribe it;
- confirm subtitles are produced;
- click a subtitle to seek;
- confirm auto-follow and locate-current;
- hide/show subtitles;
- quit the application.

After quitting, this should return no running packaged backend process:

```bash
pgrep -fl english-listening-backend
```

## 7. Test the actual DMG

Open the generated DMG, drag the application into `/Applications`, then launch that installed copy. This is a better test than launching only from `target/release/bundle/macos` because it more closely matches the eventual user flow.

## Signing / notarization boundary

A successful local `.app`/`.dmg` build proves that the app and Python sidecar can be distributed together without requiring the user's Python installation.

It does **not** yet mean the app is ready for unrestricted public distribution. Another Mac may show Gatekeeper warnings for an unsigned/unnotarized build. Developer ID signing and Apple notarization are a separate productization step after this packaging chain is proven.

## Not part of this stage

Do not add these until the v0.2 packaging chain has been verified:

- SQLite/project persistence;
- video support;
- URL import;
- podcast import;
- React/Vue migration;
- new learning features.
