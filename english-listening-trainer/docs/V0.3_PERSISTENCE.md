# v0.3 Phase 1 — Persistent Local Lesson Library

## Scope

This phase adds the minimum persistent learning loop while preserving the existing Tauri + FastAPI + faster-whisper architecture.

Implemented:

- SQLite-backed Project/Lesson records;
- permanent local copies of imported audio;
- SHA-256 media deduplication;
- persisted transcript, sentence timestamps and word timestamps;
- recent lessons list;
- reopening a saved lesson without Whisper;
- persisted playback position;
- persisted playback rate, subtitle visibility and auto-follow state;
- packaged-sidecar compatibility.

Not included:

- video;
- URL / podcast import;
- AI explanation;
- dictation;
- SRS;
- React/Vue migration.

## Local data layout

On macOS the backend creates:

```text
~/Library/Application Support/EnglishListeningTrainer/
├── app.sqlite
├── media/
│   └── <project-id>/
│       └── original.<ext>
├── cache/
│   └── tmp/
├── models/
└── logs/
```

The application owns the imported media copy. Moving or deleting the user's original file therefore does not break an existing lesson.

For isolated development/testing, override the root directory with:

```bash
ELT_DATA_DIR=/tmp/elt-test npm run tauri dev
```

## Persistence model

`projects` stores lesson metadata and current listening state.

`transcripts` stores the ASR engine/model/language metadata.

`sentences` stores sentence timestamps and text.

`words` stores word timestamps.

The media SHA-256 is unique. Importing the same bytes again returns the existing project and does not run Whisper again, provided the stored media still exists.

## API additions

```text
GET   /api/projects
GET   /api/projects/{id}
GET   /api/projects/{id}/media
PATCH /api/projects/{id}/progress
```

`POST /api/transcribe` now imports and persists a lesson. Its response includes a project id and `reused: true` when the media hash already exists.

## Development test

Pull the branch and start the normal development app:

```bash
git checkout feature/english-listening-trainer
git pull
cd english-listening-trainer
source .venv/bin/activate
npm run tauri dev
```

Test the following sequence:

1. Import a new MP3.
2. Wait for Whisper to finish.
3. Confirm the lesson appears under **Recent lessons**.
4. Play somewhere in the middle and wait a few seconds or pause playback.
5. Quit the app completely.
6. Start `npm run tauri dev` again.
7. Click the saved lesson.
8. Confirm the transcript appears immediately and the audio resumes around the previous position without Whisper running again.
9. Import the exact same MP3 again.
10. Confirm it opens the existing lesson and reports that the saved transcript was reused.
11. Toggle **Hide subtitles** and **Auto follow**, quit, reopen, and confirm those states are restored.

The database can be inspected with the macOS `sqlite3` command:

```bash
sqlite3 "$HOME/Library/Application Support/EnglishListeningTrainer/app.sqlite" \
  'select id,title,duration,playback_position,last_opened_at from projects;'
```

## Packaged app test

Because `persistence.py` is now part of the Python backend, rebuild the sidecar before testing the release app:

```bash
npm run backend:build
npm run desktop:build
```

Then quit all dev servers and open only:

```bash
open "src-tauri/target/release/bundle/macos/English Listening Trainer.app"
```

Repeat the persistence test above. The release app and development app intentionally use the same macOS application data directory unless `ELT_DATA_DIR` is overridden.

## Resetting test data

During development only, the local library can be reset by quitting the app and removing:

```bash
rm -rf "$HOME/Library/Application Support/EnglishListeningTrainer"
```

This permanently deletes the local lesson database and copied media, so use it only when intentionally resetting test data.
