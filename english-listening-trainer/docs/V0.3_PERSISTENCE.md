# v0.3 — Persistent Local Lesson Library

## Scope

v0.3 turns one-off transcriptions into a reusable local learning library while preserving the existing Tauri + FastAPI + faster-whisper architecture.

### Phase 1 — persistence foundation

Implemented:

- SQLite-backed Project/Lesson records;
- permanent local copies of imported audio;
- SHA-256 media deduplication;
- persisted transcript, sentence timestamps and word timestamps;
- recent lessons list;
- reopening a saved lesson without Whisper;
- persisted playback position;
- persisted playback rate, subtitle visibility and auto-follow state;
- packaged-sidecar compatibility.

### Phase 2 — lesson management and continue learning

Implemented:

- **Continue learning** card for the most recently studied lesson;
- visual progress bars for recent lessons;
- last-studied time in the library;
- rename lesson titles without changing the original filename;
- confirmed lesson deletion;
- deletion of the Project row and cascaded Transcript/Sentence/Word rows;
- deletion of the app-owned `media/<project-id>` directory;
- safe UI reset when the currently open lesson is deleted;
- startup retry while the packaged sidecar becomes ready;
- development API requests use the current local FastAPI origin, so the dev port can differ from the release port.

Still intentionally excluded:

- video;
- URL / podcast import;
- AI explanation;
- dictation;
- SRS;
- React/Vue migration.

## Local data layout

On macOS the backend creates:

```text
~/Library/Application Support/EnglishListeningTrainer/
├── app.sqlite
├── media/
│   └── <project-id>/
│       └── original.<ext>
├── cache/
│   └── tmp/
├── models/
└── logs/
```

The application owns the imported media copy. Moving or deleting the user's original file therefore does not break an existing lesson. Deleting a lesson removes only the app-owned copy; it never deletes the user's original source file.

For isolated development/testing, override the root directory with:

```bash
ELT_DATA_DIR=/tmp/elt-test npm run tauri dev
```

## Persistence model

`projects` stores lesson metadata and current listening state.

`transcripts` stores the ASR engine/model/language metadata.

`sentences` stores sentence timestamps and text.

`words` stores word timestamps.

The media SHA-256 is unique. Importing the same bytes again returns the existing project and does not run Whisper again, provided the stored media still exists.

Deleting a project uses SQLite foreign-key cascades to remove its transcript, sentences and words. The corresponding `media/<project-id>` directory is then removed from disk.

## API

```text
GET    /api/projects
GET    /api/projects/{id}
PATCH  /api/projects/{id}             # rename title
DELETE /api/projects/{id}             # delete lesson + local media
GET    /api/projects/{id}/media
PATCH  /api/projects/{id}/progress
POST   /api/transcribe
```

`POST /api/transcribe` imports and persists a lesson. Its response includes a project id and `reused: true` when the media hash already exists.

## Development test

Pull the branch and start the normal development app:

```bash
git checkout feature/english-listening-trainer
git pull
cd english-listening-trainer
source .venv/bin/activate
npm run tauri dev
```

Verify the complete v0.3 flow:

1. Confirm existing lessons appear under **Recent lessons** with progress bars and last-studied time.
2. Confirm the most recently studied lesson appears in **Continue learning**.
3. Play a lesson, quit, reopen, click **Continue lesson**, and confirm playback resumes around the saved position.
4. Rename a lesson and confirm the new title remains after restarting the app.
5. Click **Delete**, cancel the confirmation once, and confirm nothing is removed.
6. Delete a non-current lesson and confirm it disappears from the library.
7. Delete the currently open lesson and confirm the player/transcript workspace resets cleanly.
8. Re-import an existing audio file and confirm SHA-256 deduplication still reuses its saved transcript.
9. Confirm playback position, subtitle visibility and auto-follow still persist across restarts.

The database can be inspected with:

```bash
sqlite3 "$HOME/Library/Application Support/EnglishListeningTrainer/app.sqlite" \
  'select id,title,duration,playback_position,last_opened_at from projects order by last_opened_at desc;'
```

To verify cascade deletion for a known project id before and after deleting it in the UI:

```bash
sqlite3 "$HOME/Library/Application Support/EnglishListeningTrainer/app.sqlite" \
  'select p.id,t.id,(select count(*) from sentences s where s.transcript_id=t.id) from projects p join transcripts t on t.project_id=p.id;'
```

## Packaged app test

Rebuild the Python sidecar and release bundle because both backend code and the packaged static UI changed:

```bash
npm run backend:build
npm run desktop:build
```

Quit all development servers and open only the release app:

```bash
open "src-tauri/target/release/bundle/macos/English Listening Trainer.app"
```

Repeat the Phase 2 tests above. In particular, verify **Continue learning**, rename, delete, deletion of the current lesson, restart persistence and SHA-256 reuse.

After deleting a lesson, its media directory should no longer exist under:

```text
~/Library/Application Support/EnglishListeningTrainer/media/<project-id>/
```

The release app and development app intentionally use the same macOS application data directory unless `ELT_DATA_DIR` is overridden.

## Resetting test data

During development only, the local library can be reset by quitting the app and removing:

```bash
rm -rf "$HOME/Library/Application Support/EnglishListeningTrainer"
```

This permanently deletes the local lesson database and copied media, so use it only when intentionally resetting test data.
